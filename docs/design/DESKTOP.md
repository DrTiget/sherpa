# Sherpa — виртуальный рабочий стол сервера (концепция)

Статус: дизайн после MVP. Стиль — v2 (Kali/KDE), тулкит Qt 6 / QML (см. `SCREENS.md`, разделы 5–6).
Прототип: кликабельный HTML-прототип в `docs/design/prototype/` (запуск и параметры — `prototype/README.md`). Он — актуальный макет рабочего стола; скриншоты — `frontend/screenshots/`.

Идея: открыв сервер, пользователь попадает не в карточку, а на **рабочий стол этого сервера**: обои, панель задач, лаунчер и окна утилит. Всё работает поверх SSH (по-прежнему без агентов на сервере): утилиты запускают на сервере стандартные команды и читают `/proc`, `/sys`, `systemd`, `journalctl`, SFTP; ядро (`sherpa-core`) превращает это в структурированные данные.

## 1. Как рабочий стол связан со списком серверов

Список серверов (главное окно MVP) становится **«домом» — стартовым экраном и менеджером рабочих столов**:

```
Sherpa
 ├─ Дом (список серверов, группы, теги, статусы)  ← текущее главное окно MVP
 ├─ Рабочий стол: web-01   ┐
 ├─ Рабочий стол: db-main  ├ вкладки верхнего уровня (как рабочие столы)
 └─ Рабочий стол: gw-eu    ┘
```

- **Вкладки верхнего уровня.** Первая вкладка «Дом» неподвижна. Двойной клик по серверу (или кнопка «Рабочий стол» в карточке) открывает вкладку с рабочим столом; кнопка «Терминал» в карточке остаётся быстрым путём — открывает рабочий стол с одним окном терминала.
- **Несколько серверов.** Каждый рабочий стол — отдельное SSH-соединение и независимый набор окон. Переключение: Ctrl+Tab, Ctrl+1…9, клик по вкладке. Вкладка показывает цветной индикатор статуса и имя; красная точка при обрыве.
- **Сводный обзор.** Ctrl+Space (или кнопка «Рабочие столы» в панели) показывает **обзор**: плитки всех открытых серверов с миниатюрами (как KDE Overview), статусом и мини-метриками CPU/RAM. Из обзора можно закрыть рабочий стол или открыть «Дом».
- **Док «Дом» внутри рабочего стола.** В левой части панели задач — кнопка «Серверы»: выезжающая боковая панель (поиск, группы, статусы) для быстрого перехода на другой сервер, не покидая рабочий стол. Это тот же список, что и на «Доме», только компактный.
- **Состояние сохраняется.** Раскладка окон, обои и закреплённые в панели утилиты хранятся в БД ядра по подключению (`desktop.state.*`) и восстанавливаются при следующем открытии.

## 2. Устройство рабочего стола

```
┌ вкладки: [Дом] [web-01 ●] [db-main ●] [+]                                  ┐
│                                                                             │
│   Обои (на сервер — свои, акцентный цвет по группе)       ┌ окно ───────┐   │
│   Иконки: Терминал, Файлы, Монитор …                       │             │   │
│                                                           └─────────────┘   │
│ ┌ панель задач ──────────────────────────────────────────────────────────┐ │
│ │ [S Лаунчер] [Серверы] │ [окна…] │            трей: CPU RAM NET ⏱ 🔔 14:02 │ │
│ └────────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Окна
- Окна утилит — перемещаемые, изменяемые по размеру, с кнопками «свернуть / развернуть / закрыть». Заголовок: иконка, название утилиты, имя сервера (чтобы не перепутать при нескольких).
- Полупрозрачные (74%) с blur 30 px, как в v2; активное окно ярче и со свечением акцента, неактивные тусклее.
- Привязка к краям (snap): к половинам и четвертям экрана при перетаскивании к краю, Ctrl+Alt+стрелки.
- Свёрнутое окно живёт в панели задач, щелчок по значку разворачивает, колёсико/наведение показывает миниатюру.
- Окна из одной утилиты можно открывать несколько раз (терминалы, файловые менеджеры); монитор, сеть, система, диски — по одному на сервер.
- Вся раскладка — QML-компоненты `SWindow` (`Item` с перетаскиванием, resize-хэндлами, `MultiEffect` для blur); окна не являются окнами ОС. Подробности — раздел 7.

### 2.2 Панель задач (снизу, 44 px, тоже blur)
Слева направо:
1. **Лаунчер** — кнопка с логотипом Sherpa (открывает меню, 2.3).
2. **Серверы** — компактный список для переключения рабочего стола.
3. **Закреплённые утилиты и открытые окна.** Закреплённые — значки, открытые подсвечены полоской акцента, с активным — яркая.
4. **Трей** (справа): индикаторы сервера в реальном времени (по `monitor.subscribe`):
   - CPU (мини-бар и %), RAM (%), сеть (↓/↑ скорость), uptime;
   - значок **Центра уведомлений** со счётчиком;
   - значок состояния соединения (задержка в мс, зелёный/жёлтый/красный);
   - часы сервера с часовым поясом (при наведении — время и пояс сервера против локального).
   Клик по индикатору открывает «Монитор ресурсов», по сетевому — «Сеть», по часам — календарь/время в «Системе».

### 2.3 Лаунчер (как меню KDE/Kali)
- Открывается кнопкой, клавишей Meta/Super (если ОС не перехватывает) или Ctrl+Space; всплывающая панель 560×620 с blur.
- Сверху — **поле поиска** по утилитам, **службам, пакетам, файлам и командам** («nginx» → служба nginx, пакет, файл конфигурации, лог).
- Слева — категории: Избранное, Система, Сеть, Файлы, Мониторинг, Разработка, Все приложения; справа — сетка значков утилит; ниже — недавние файлы и последние команды.
- Внизу — действия с сервером: «Переподключиться», «Блокировать рабочий стол», «Перезагрузить сервер…», «Выключить сервер…» (опасные — с подтверждением, см. 2.6), «Закрыть рабочий стол».
- Контекстное меню значка: «Закрепить в панели», «Добавить на рабочий стол», «Открыть новое окно».

### 2.4 Рабочий стол (иконки и обои)
- На обоях — ярлыки (по умолчанию: Терминал, Файлы, Монитор, Службы), перетаскиваются, сетка.
- Виджеты (опционально): «Диски», «Топ процессов», «Службы с ошибками». Минимум на первом этапе — один виджет «Сводка» (uptime, load, IP).
- Обои выбираются по серверу: цветной градиент, имя сервера крупно полупрозрачным текстом (чтобы видеть, где вы), цвет — по группе (Prod — красный оттенок, Stage — жёлтый и т. п. — защита от ошибок на продакшене).
- Контекстное меню рабочего стола: «Новый терминал», «Файлы здесь», «Обои…», «Упорядочить значки».

### 2.5 Состояния рабочего стола
| Состояние | Что видит пользователь |
|-----------|------------------------|
| Подключение | Обои, по центру карточка «Подключение к web-01…» со спиннером и шагами (TCP → host key → вход → готово). Панель неактивна. Ошибка — карточка с причиной и «Повторить» / «Изменить подключение» |
| Host key | Стандартный диалог host key (SCREENS 2.6) поверх рабочего стола |
| Готово, данные подгружаются | Окна открываются сразу, внутри — скелетон (серые полосы), трей — прочерки `—` |
| Обрыв | Рабочий стол остаётся, окна затемнены (насыщенность −50%), баннер сверху «Соединение потеряно · переподключение через 5 с · Повторить сейчас». Терминалы показывают «сессия отключена»; передачи файлов приостановлены с возможностью возобновить |
| Переподключение | Автоповтор с растущей паузой (1–30 с, настройка); после успеха окна оживают, сессии терминала переподключаются (демон держит их 30 с, см. `CORE_API.md` §4.2) |
| Нет прав (sudo) | Информационный значок «щит» в панели; утилиты, требующие root, показывают баннер «Нужны права root. [Ввести пароль sudo] [Работать только на чтение]». Пароль sudo вводится в диалоге, не сохраняется на диск (опция «Запомнить на сессию» — только в памяти демона) |
| Только чтение | Режим «Наблюдатель» (переключатель в панели): все изменяющие действия отключены, остаётся просмотр |
| Нет утилит на сервере | Если на сервере нет `ss`, `journalctl`, `docker` и т. п., окно показывает «Недоступно на этом сервере: не найден docker» и подсказку, как установить |
| ОС не поддерживается | MVP рабочего стола — Linux-серверы (systemd). Другие ОС: часть утилит (терминал, файлы) работает, остальные неактивны с пояснением |

### 2.6 Опасные действия — единые правила
- Любое необратимое или рискованное действие (удалить файлы, kill процесса, остановить службу, изменить firewall, перезагрузить сервер, `apt remove`, удалить пользователя) идёт через **диалог подтверждения**: красный заголовок, перечисление затронутого, имя сервера крупно, действие по умолчанию — «Отмена».
- Для критичных (перезагрузка, выключение, firewall, остановка sshd, удаление пользователей/каталогов с > N файлами) подтверждение требует **ввода имени сервера**.
- **Защита от потери связи:** изменение firewall и сетевых настроек сопровождается таймером отката («Если вы не подтвердите за 60 с, изменения будут отменены») — реализует ядро.
- Группа «Prod» усиливает предупреждения (красная полоса в заголовке окна).
- Все действия записываются в журнал рабочего стола (кто, что, когда, результат) — доступен из «Центра уведомлений».

| Рабочий стол №N | Ctrl+1…9 |

| Привязка окна | Ctrl+Alt+←/→/↑/↓ |

## 3. Общие элементы утилит
Окно утилиты: заголовок (иконка, имя, сервер), меню-«гамбургер», панель инструментов (поиск, обновить, автообновление), область содержимого, статус-строка (источник данных, время обновления, права: `user` / `root`). Все списки: сортировка по колонкам, поиск, контекстное меню, мультивыбор. Состояния: скелетон при загрузке, «пусто» с подсказкой, «ошибка» с кодом и «Повторить», баннер «нужны права». Моноширинный шрифт для данных (пути, адреса, PID), статусы — яркие точки.

## 4. Утилиты

Для каждой утилиты: назначение → экраны и элементы → действия → опасные действия → данные от ядра. Команды ядра перечислены кратко; формат — `группа.действие` (в CLI `sherpa-core <группа> <действие>`, для потоков — методы демона, см. §6).

### 4.1 Терминал
- **Назначение:** интерактивный shell (PTY), как в MVP (SCREENS 2.4), но в окне рабочего стола.
- **Элементы:** вкладки внутри окна, поиск по выводу (Ctrl+Shift+F), разделение панелей (Ctrl+Shift+D/E), профиль цветов, кнопка «Открыть файлы здесь», клик по пути/ссылке открывает файловый менеджер или браузер, копировать/вставить, масштаб Ctrl +/−. Прозрачность 62% с blur, промпт в стиле Kali.
- **Состояния:** подключение, обрыв («сессия отключена» + «Переподключить»), завершение (`exit`).
- **Опасные действия:** вставка многострочного текста — предупреждение «вставка содержит переводы строк»; закрытие окна с активным процессом — подтверждение.
- **Данные ядра:** `session.open|input|resize|close|attach` (уже есть, демон), событие `session.output`; для «Открыть файлы здесь» — текущий каталог (`session.cwd`, по OSC 7/`/proc/<pid>/cwd`).

### 4.2 Файловый менеджер (SFTP)
- **Назначение:** просмотр и управление файлами сервера, перенос с локального компьютера, правка текстов.
- **Экраны и элементы:**
  - три зоны: дерево каталогов слева (с «Избранным» и закладками), список/иконки по центру, панель свойств справа (скрываемая);
  - переключатель вида «Список / Иконки / Компактно», сортировка, показ скрытых файлов, строка пути (хлебные крошки + ввод), поиск (по имени, `find`);
  - колонки: имя, размер, изменён, владелец:группа, права (`rwxr-xr-x` + восьмеричные);
  - drag&drop: из ОС на окно — загрузка; из окна в ОС — скачивание; между двумя окнами (двухпанельный режим) — копирование; Ctrl при перетаскивании — копировать;
  - панель передач внизу: список заданий, прогресс, скорость, оставшееся время, пауза/отмена/повтор;
  - диалог «Свойства»: права (флажки r/w/x для владельца/группы/остальных, рекурсивно), владелец и группа, символьная ссылка, размер каталога;
  - **редактор текстовых файлов** (отдельное окно): подсветка синтаксиса, нумерация строк, поиск/замена, кодировка и окончания строк, сохранить (Ctrl+S) с проверкой, что файл не изменился на сервере (`etag` по mtime/size), «Сохранить как root» (через sudo), открытие больших файлов постранично (> 5 МиБ — только чтение).
- **Действия:** создать файл/каталог, переименовать, копировать, переместить, удалить, права и владелец, ссылка, архивировать/распаковать (tar/zip на сервере), скачать, загрузить, открыть в редакторе/терминале.
- **Опасные:** удаление (диалог со списком; для каталогов — число файлов, для системных путей `/etc`, `/boot`, `/usr` — ввод имени сервера), рекурсивные chmod/chown, перезапись при конфликте (спросить: заменить/пропустить/оба/переименовать), сохранение в системные файлы.
- **Данные ядра:** `fs.list`, `fs.stat`, `fs.mkdir`, `fs.rename`, `fs.copy`, `fs.move`, `fs.remove`, `fs.chmod`, `fs.chown`, `fs.symlink`, `fs.read` (с диапазоном), `fs.write` (с `if_match`), `fs.search`, `fs.archive`, `fs.du` (размер каталога); передачи: `transfer.upload|download|list|pause|resume|cancel`, события `transfer.progress|done|error`.

### 4.3 Монитор ресурсов
- **Назначение:** текущая нагрузка и процессы; аналог System Monitor/htop.
- **Вкладки:** «Обзор», «Процессы», «Сеть», «Датчики» (если есть).
- **Обзор:**
  - CPU: общий график (60 с, 5 мин, 1 ч), столбцы **по ядрам** (heat-bars), user/system/iowait/steal;
  - память: RAM (used/cache/buffers/free) и swap, график;
  - load average (1/5/15), uptime, число процессов/потоков;
  - сеть: график ↓/↑ по интерфейсам, суммарная скорость; диски: чтение/запись IOPS и МБ/с;
  - температуры и частоты CPU (если доступны `/sys`).
- **Процессы:** таблица PID, имя, пользователь, CPU %, RAM %, RSS, состояние, команда, время; сортировка, фильтр, дерево процессов, группировка по пользователю. Выбор процесса — панель: открытые файлы, сокеты, потоки, переменные окружения (по `sudo`), nice, cgroup/служба.
- **Действия:** завершить (SIGTERM), принудительно (SIGKILL), другие сигналы (меню), **renice** (ползунок −20…19), пауза/продолжить (STOP/CONT), «Показать в службах», автообновление (1/2/5 с, пауза).
- **Опасные:** kill процессов других пользователей/root, PID 1, `sshd` (может отрезать связь) — подтверждение с именем процесса и PID; для критичных — ввод имени сервера; renice < 0 требует root.
- **Данные ядра:** `monitor.snapshot` (разовый), подписка `monitor.subscribe {interval, parts:[cpu,mem,net,disk,load]}` → события `monitor.tick`; `proc.list`, `proc.info`, `proc.signal`, `proc.renice`; источники — `/proc/stat`, `/proc/meminfo`, `/proc/net/dev`, `/proc/<pid>`.

### 4.4 Анализ дисков
- **Назначение:** понять, чем занято место, найти крупные файлы.
- **Экраны:**
  - **Разделы:** список устройств и точек монтирования (устройство, ФС, точка, размер, занято, свободно, inode%, опции монтирования), полоска заполненности с цветом по порогам (зелёный < 70%, жёлтый < 90%, красный ≥ 90%), блочные устройства (дерево `lsblk`), SMART (если доступно).
  - **Карта (sunburst / treemap):** выбор каталога или раздела → сканирование с прогрессом → интерактивная диаграмма; клик — вход в каталог, крошки сверху, переключатель «Sunburst / Treemap / Список»; справа список крупнейших объектов с размером и долей; цвета по типам (логи, архивы, образы, кэш, БД).
  - **Крупные файлы:** фильтры: порог размера, возраст, расширение, владелец; сортировка; результат — таблица с «Показать в файлах», «Удалить…», «Архивировать».
  - **Подсказки очистки:** apt-кэш, старые ядра, журналы journald, Docker (образы/тома), старые логи — с оценкой освобождаемого места и кнопкой «Очистить…».
- **Опасные:** удаление файлов и очистка (диалог со списком и общим размером; «Prod» — ввод имени сервера); сканирование корня нагружает диск — предупреждение и опция «низкий приоритет (ionice)».
- **Данные ядра:** `disk.list` (df/lsblk/findmnt), `disk.scan {path, depth, one_filesystem}` → события `disk.scan.progress|done` (дерево размеров, может частично), `disk.large {path, min_size, ...}`, `disk.cleanup.suggest`, `disk.cleanup.run` (через `fs.remove`/`pkg.clean`/`journal.vacuum`/`docker.prune`).

### 4.5 Настройки сети
- **Назначение:** просмотр и изменение сетевой конфигурации, диагностика.
- **Вкладки:**
  1. **Интерфейсы:** список (имя, статус, MAC, IPv4/IPv6, MTU, скорость, ↓/↑); карточка интерфейса: адреса (добавить/удалить), включить/выключить, DHCP/статический (через netplan / NetworkManager / systemd-networkd — ядро определяет, чем управляется).
  2. **Маршруты:** таблица маршрутов (dst, via, dev, metric), шлюз по умолчанию, добавить/удалить.
  3. **DNS:** серверы, search-домены, `/etc/hosts` (редактор таблицей), проверка резолва (`dig`-подобная).
  4. **Порты и сокеты:** слушающие порты (протокол, адрес, порт, PID/процесс, пользователь, состояние), установленные соединения (с поиском и фильтром), «Кто слушает этот порт», быстрые действия: «Завершить процесс», «Открыть правило firewall».
  5. **Firewall:** определяет `ufw` / `nftables` / `firewalld` / `iptables`; список правил (порядок, действие allow/deny, направление, протокол, порт/диапазон, источник, комментарий), переключатель «Firewall включён», форма добавления (шаблоны «SSH», «HTTP/HTTPS», «PostgreSQL»…), перетаскивание порядка, предпросмотр итоговой команды/диффа.
  6. **Диагностика:** ping, traceroute, проверка порта (TCP connect), speedtest (опция).
- **Опасные:** изменение адреса/маршрута/DNS/firewall на интерфейсе, по которому идёт SSH, — **откат по таймеру** (60 с; сначала `apply --confirm`); блокировка порта SSH — красное предупреждение «вы потеряете доступ»; включение firewall без правила SSH — запрещено без явного подтверждения; удаление правил — подтверждение.
- **Данные ядра:** `net.iface.list|set`, `net.addr.add|del`, `net.route.list|add|del`, `net.dns.get|set`, `net.hosts.get|set`, `net.sockets {listening, established}`, `net.test.{ping,trace,port,resolve}`, `fw.status`, `fw.rules.list`, `fw.rule.add|del|move`, `fw.enable|disable`, `net.apply {confirm_timeout}` / `net.confirm` / `net.rollback`.

### 4.6 Настройки системы
- **Назначение:** базовое администрирование.
- **Вкладки:**
  1. **Общее:** hostname, ОС и версия, ядро, архитектура, uptime, перезагрузить / выключить сервер (опасные), сведения о железе (CPU, RAM, виртуализация).
  2. **Время:** время и часовой пояс (поиск), NTP вкл/выкл и серверы, синхронизация, разница с локальным временем.
  3. **Пользователи и группы:** списки; пользователь: имя, UID, домашний каталог, shell, группы, блокировка, срок пароля, **SSH-ключи** (authorized_keys: добавить/удалить, отпечатки), sudo-доступ; создать, изменить, сменить пароль, удалить (с домашним каталогом или без).
  4. **Пакеты (apt/dnf/…):** вкладки «Обновления» (список обновляемых, безопасность отдельно, «Обновить выбранные/все»), «Установленные», «Поиск и установка», «Репозитории»; прогресс и вывод в панели «Журнал операции»; автообновления (unattended-upgrades).
  5. **Службы (systemd):** таблица (имя, описание, состояние active/failed/inactive, автозапуск, пользователь, память); фильтры «Только сбойные», «Только запущенные»; карточка: статус, последние строки журнала, зависимости, юнит-файл (просмотр/правка с `daemon-reload`); действия: запустить, остановить, перезапустить, перезагрузить конфиг, включить/выключить автозапуск, маскировать.
  6. **Таймеры:** systemd-таймеры (следующий запуск, последний запуск).
- **Опасные:** остановка/отключение `sshd`, сети, `systemd-*`; удаление пользователей; `apt remove/purge` (покажет зависимости, которые будут удалены); полное обновление (`dist-upgrade`) на Prod; смена hostname на продакшене; перезагрузка/выключение — ввод имени сервера; правка юнит-файла — подсказка о риске.
- **Данные ядра:** `sys.info`, `sys.hostname.set`, `sys.power {reboot|shutdown, delay}`, `time.get|set_zone|ntp`, `user.list|add|set|del|passwd`, `group.list|add|del`, `user.keys.list|add|del`, `pkg.detect` (apt/dnf/…), `pkg.updates`, `pkg.search`, `pkg.installed`, `pkg.install|remove|upgrade` (потоковый вывод — события `pkg.output`), `pkg.repos`, `svc.list`, `svc.status`, `svc.{start,stop,restart,reload,enable,disable,mask}`, `svc.unit.get|set`, `timer.list`.

### 4.7 Логи
- **Назначение:** читать журналы и файлы логов, искать причину проблем.
- **Элементы:** левая колонка — источники (journald: «Система», «Ядро», по службам; файлы `/var/log/*`; Docker-контейнеры), фильтры сверху: период (быстрые: 15 мин, 1 ч, сегодня, диапазон), приоритет (emerg…debug, цветные метки), служба/юнит, процесс, пользователь, текст/regex, boot (текущая/предыдущая загрузка); просмотр: строки с временем, источником, текстом, подсветка уровня, раскрытие записи (все поля journald), кнопка «Следить (tail -f)» с автопрокруткой, пауза; «Скопировать», «Сохранить в файл», «Открыть в терминале».
- **Состояния:** «Нет записей по фильтру», «Нужны права (группа systemd-journal/adm)» с кнопкой sudo.
- **Опасные:** «Очистить журнал» (`journalctl --vacuum`) — подтверждение; ротация логов.
- **Данные ядра:** `log.sources`, `log.query {unit, priority, since, until, grep, boot, lines, cursor}`, `log.follow` → события `log.line`, `log.vacuum`, `log.file.tail`.

### 4.8 Планировщик (cron и systemd-таймеры)
- **Назначение:** управление периодическими задачами.
- **Элементы:** вкладки «Cron пользователя», «Системный cron» (`/etc/cron.d`), «Таймеры systemd»; таблица (расписание человекочитаемо: «каждый день в 03:00», команда, пользователь, состояние, последний/следующий запуск); редактор задачи: конструктор расписания (минуты/часы/дни/месяцы/дни недели, пресеты) + выражение cron + предпросмотр «следующие 5 запусков», команда, окружение, комментарий, вывод в почту/файл; «Запустить сейчас», включить/выключить (комментированием), удалить; журнал выполнения (из логов).
- **Опасные:** удаление задач; запуск команд от root; предупреждение при `*` в минутах.
- **Данные ядра:** `cron.list {user}`, `cron.add|set|del|toggle`, `cron.run`, `cron.history`, `timer.list|enable|disable|run` (общее с 4.6).

### 4.9 Docker
- **Назначение:** управление контейнерами на сервере.
- **Вкладки:** «Контейнеры» (имя, образ, состояние, порты, CPU/RAM, uptime; запуск, стоп, рестарт, пауза, удаление; логи, терминал `exec`, инспекция), «Образы» (теги, размер; pull, удалить, prune), «Тома», «Сети», «Compose» (проекты, `up/down/pull`), «Логи» (потоковые, как в 4.7).
- **Опасные:** удаление контейнера/тома (данные!), `prune` — подтверждение со списком и размером; остановка контейнеров на Prod — ввод имени сервера.
- **Состояния:** «Docker не установлен» (подсказка), «Нет прав (группа docker)».
- **Данные ядра:** `docker.ping`, `docker.ps`, `docker.inspect`, `docker.{start,stop,restart,pause,rm}`, `docker.logs {follow}`, `docker.exec` (через PTY-сессию), `docker.images|pull|rmi|prune`, `docker.volumes|networks`, `docker.stats` (подписка), `docker.compose.{list,up,down,pull}`.

### 4.10 Центр уведомлений
- **Назначение:** события рабочего стола и сервера в одном месте.
- **Элементы:** значок в трее со счётчиком; выезжающая справа панель: группировка по серверам и времени; типы: обрыв/восстановление связи, превышение порогов (диск > 90%, RAM > 90%, load, служба упала, высокая температура), завершение передач/обновлений, предупреждения безопасности (смена host key, вход по SSH с нового IP, много неудачных попыток), результаты cron; фильтры и «Не беспокоить»; действия на уведомлении: «Открыть монитор / логи / службу».
- **Настройки правил:** пороги и длительность, каналы (в приложении, системное уведомление ОС), тишина по расписанию.
- **Журнал действий** (вкладка): кто и что делал на рабочем столе (опасные операции, результат).
- **Данные ядра:** `notify.rules.list|set`, `notify.list|read|clear`, события `notify.new`; проверки — по `monitor.subscribe` и `svc.watch` внутри демона; журнал — `audit.list`. Работает только пока приложение/демон запущены (без агента на сервере).

### 4.11 Расширенный набор утилит

Эти утилиты входят в концепцию наравне с 4.1–4.10 (в прототипе они уже есть, на вымышленных данных). Общие правила (опасные действия, права, capabilities, режим «Наблюдатель») те же.

**4.11.1 Веб-серверы и SSL** (`web`). Вкладки «Сайты» (виртуальные хосты nginx/apache: домен, корень, порты, SSL, включение/отключение, правка vhost в редакторе), «Сертификаты» (срок действия с цветовой шкалой, «Продлить», `certbot renew --dry-run`), «Конфиг». Кнопки в панели: «nginx -t» (проверка, вывод по строкам) и «Reload» (запрещён, пока проверка не пройдена; подтверждение на Prod). Опасное: reload/restart, правка конфига, отключение сайта. Ядро: `web.detect`, `web.sites.list|get|set|enable|disable`, `web.test`, `web.reload`, `web.certs.list`, `web.certs.renew`.

**4.11.2 Базы данных** (`db`). PostgreSQL, MySQL, Redis: список баз (размер, владелец, подключения), активные запросы (длительность, состояние, «Kill…»), «Дамп…» (выбор базы и формата, результат в `/var/backups`), для Redis — память, ops/s, клиенты, keyspace и «FLUSHDB…». Работает в режиме только чтения (запросы пользователя не выполняются), порты БД наружу не открываются. Опасное: kill запроса, FLUSHDB (ввод имени сервера), дамп больших баз. Ядро: `db.detect`, `db.list`, `db.queries`, `db.kill`, `db.dump` (потоковый), `redis.info`, `redis.flush`.

**4.11.3 Безопасность** (`sec`). «Обзор» (оценка 0–100 и рекомендации), fail2ban (jails, баны, «Разбанить», «Забанить IP»), «Входы» (неудачные попытки за сутки, «Заблокировать», активные сессии), «Ключи» (authorized_keys всех пользователей, предупреждение о слабых ключах, удаление), «Порты» (слушающие наружу с оценкой риска, «Закрыть…» через firewall с откатом), «Обновления» (только security-патчи). Опасное: удаление ключей (для root — ввод имени сервера), закрытие портов, бан. Ядро: `sec.score`, `sec.fail2ban.*`, `sec.logins`, `sec.sessions`, `sec.keys.list|del`, `sec.ports`, `pkg.updates --security`.

**4.11.4 Сниппеты** (`snip`). Библиотека команд (название, команда, теги) и запуск на этом сервере, на группе или на всех серверах; результат по каждому серверу (код выхода, время, вывод), история. Команды с `rm -rf`, `reboot`, `restart`, `upgrade` и т. п. при запуске на нескольких серверах или на Prod требуют подтверждения (при нескольких серверах — ввод слова «выполнить»). Ядро: `snippet.list|set|del`, `run.exec {targets, command}` (потоковые события по каждому серверу), `run.history`.

**4.11.5 Мультисервер** (`multi`). Выбор серверов по группам, одна команда, таблица результатов и режим «Сравнение» (группировка серверов с одинаковым выводом: «6 из 8 — 6.8.0, 2 — 5.15.0»). Быстрые команды, таймаут 10 с, параллельное выполнение через демон. Ядро: `batch.run`, `batch.status`, события `batch.result`.

**4.11.6 Туннели** (`tun`). Проброс портов SSH: `-L` (удалённый сервис открывается локально на 127.0.0.1), `-R` (локальный сервис становится доступен на сервере), `-D` (SOCKS). Список (тип, локальный/удалённый адрес, трафик), старт/стоп, «Открыть в браузере» для `-L`, показ эквивалентной команды `ssh`. Проверка занятости порта. Опасное: `-R` (подтверждение с описанием, кто получит доступ). Ядро: `tunnel.list|set|del|start|stop`, события `tunnel.stats`.

**4.11.7 Бэкапы** (`bak`). Задания restic/rsync (источник → хранилище S3/SFTP, расписание, последний запуск, размер), «Запустить», снимки и «Восстановить…» (цель, `--dry-run` по умолчанию), проверка целостности, `prune`. Опасное: восстановление поверх исходных данных (ввод имени сервера), prune. Ядро: `backup.jobs.list|set|del`, `backup.run`, `backup.snapshots`, `backup.restore`, `backup.check`, `backup.prune`.

**4.11.8 Сравнение конфигов** (`diff`). Файл (из списка избранных конфигов) → источник слева и справа: другой сервер, текущая версия, версия «вчера», «12.10»; построчный diff в две колонки, «только различия», «Применить справа…» (с резервной копией `.bak`). Опасное: применение на сервер (Prod — ввод имени). Ядро: `cfg.read {server, path, version}`, `cfg.diff`, `cfg.apply`, `cfg.history`.

**4.11.9 Сетевые инструменты** (`nettools`). `ping`, `traceroute`, `dig` (A/AAAA/MX/TXT/NS), `curl -I`, проверка порта, `speedtest` — выполняются **на сервере**, вывод потоком. Ядро: `net.test.{ping,trace,dig,curl,port,speed}` (потоковые).

**4.11.10 Журнал Sherpa** (`audit`). Что и кто делал на серверах через приложение: время, пользователь/клиент, сервер, раздел, действие, итог; фильтры по серверу и пользователю, поиск, экспорт CSV. В журнале только описания операций, без секретов; хранится в БД ядра (по умолчанию 90 дней). Ядро: `audit.list {filters}`, `audit.export`.

**4.11.11 Заметки и секреты** (`notes`). Markdown-заметки сервера (редактор/просмотр) и хранилище паролей сервисов (Grafana, phpMyAdmin и т. п.): шифрование тем же ключ-файлом, показ значения только после подтверждения и на 10 секунд, копирование с автоочисткой буфера, запись факта просмотра в журнал. Ядро: `notes.list|get|set|del`, `vault.list|reveal|set|del`.

**4.11.12 Виджеты на обоях** (плазмоиды). Карточки с blur прямо на рабочем столе: «CPU» (график), «Диски» (заполненность), «Сервер» (uptime, load, RAM, ОС), «Алерты» (последние уведомления), «Время сервера». Перетаскиваются по обоям, набор включается в контекстном меню рабочего стола («Виджеты…»), расположение хранится в `desktop.state`. Данные берутся из тех же подписок `monitor.subscribe` и `notify.list`, что и трей.

Дополнительно можно рассмотреть (не в прототипе): менеджер SSL/сертификатов отдельно от веб-серверов, `cron` для нескольких серверов, сравнение установленных пакетов между серверами, мониторинг URL (доступность сайтов).

## 5. Данные и протокол: что нужно ядру (кратко, для CORE_API.md)

Новые группы команд (все работают через SSH-сессию, канал `exec`/SFTP, без агента):

| Группа | Назначение |
|--------|------------|
| `web.*`, `db.*`, `redis.*` | веб-серверы, SSL, базы данных |
| `sec.*` | безопасность |
| `snippet.*`, `run.*`, `batch.*` | сниппеты и мультисервер |
| `tunnel.*` | туннели |
| `backup.*` | бэкапы |
| `cfg.*` | конфиги и diff |
| `notes.*`, `vault.*` | заметки и секреты |
| `desktop.*` | `state.get|set` (раскладка окон, обои, закрепы), `open {conn}` (подготовить соединение, проверить возможности), `capabilities` |
| `sys.*`, `time.*`, `user.*`, `group.*`, `pkg.*`, `svc.*`, `timer.*` | настройки системы |
| `fs.*`, `transfer.*` | файлы, редактор, передачи |
| `monitor.*`, `proc.*` | ресурсы и процессы |
| `disk.*` | разделы, сканирование, чистка |
| `net.*`, `fw.*` | сеть, firewall, откат по таймеру |
| `log.*` | journald и файлы |
| `cron.*` | cron |
| `docker.*` | Docker |
| `notify.*`, `audit.*` | уведомления, журнал действий |
| `priv.*` | `sudo.check`, `sudo.auth` (пароль sudo в памяти), `readonly.set` |

Принципы:
- **Capabilities.** При открытии рабочего стола ядро один раз определяет возможности сервера (`desktop.capabilities`): ОС и версию, systemd, пакетный менеджер, наличие `ss`, `docker`, `ufw`/`nft`, права текущего пользователя (root/sudo/NOPASSWD), набор доступных утилит. Фронт скрывает/отключает окна по этому ответу.
- **Одноразовые и потоковые.** Короткие запросы (`fs.list`, `svc.list`) — обычные запросы к демону; длинные и потоковые (`monitor.subscribe`, `log.follow`, `disk.scan`, `transfer.*`, `pkg.install`) — события демона (см. `CORE_API.md` §4.4). Рабочий стол **всегда использует демон**: он держит SSH-соединение, мультиплексирует каналы и переподключается.
- **Мультиплексирование.** Одно SSH-соединение на сервер, внутри — каналы под каждую утилиту; лимит одновременных каналов настраивается. Тяжёлые операции (скан диска) идут с низким приоритетом (`nice`, `ionice`).
- **Привилегии.** Операции, требующие root, выполняются через `sudo -n` (если NOPASSWD) или `sudo -S` с паролем, который вводит пользователь и который хранится только в памяти демона на время сессии. Ядро возвращает ошибку `priv.required`, фронт показывает баннер.
- **Опасные операции.** Ядро принимает флаг `confirm_token`, выданный отдельным вызовом `danger.prepare` (фронт показывает пользователю список затрагиваемого), — защита от случайного вызова. Для сети — `net.apply` с таймером отката.
- **Структурированные данные.** Ядро парсит вывод утилит (`ss -tulnp`, `df`, `systemctl`, `journalctl -o json`) в JSON; фронты не парсят текст.
- **Безопасность.** Секреты и пароль sudo не попадают в логи и журнал; журнал действий хранит только описание операции.
- **Ошибки.** Новые коды: `priv.required`, `cap.missing`, `fs.conflict`, `fs.not_found`, `fs.permission`, `svc.failed`, `pkg.locked`, `net.rollback`, `desktop.not_supported`.

## 6. Требования к QML-фронту (дополнение)
- `SDesktop` — корневой компонент: обои, `SWindowManager` (стек окон, z-order, фокус, snap), `STaskbar`, `SLauncher`, `SOverview`, `SNotifyCenter`.
- `SWindow` — общий компонент окна: заголовок, drag, resize, minimize/maximize/close, blur через `MultiEffect` + `ShaderEffectSource` (накладные расходы: > 8 окон с blur — деградация до непрозрачных; настройка «Эффекты»).
- Утилиты — отдельные QML-модули (`apps/terminal`, `apps/files`, …), подключаются через реестр утилит; в реестре — id, иконка, категория, требуемые capabilities и права. Новая утилита = модуль + команды ядра.
- Данные утилит — модели (`QAbstractListModel`) над событиями демона; утилиты не вызывают SSH сами.
- Состояние окон (позиция, размер, свёрнуто) сохраняется в ядро (`desktop.state.set`) с задержкой.
- Графики (CPU, сеть, диски) — `Canvas`/`QtQuick.Shapes`; sunburst/treemap — `Shape` + hit-testing.

## 7. Этапы (рекомендация)
1. **Основа:** `SWindow`, панель, лаунчер, обои, несколько рабочих столов, терминал, `desktop.capabilities`.
2. **Файлы** (SFTP + редактор + передачи) и **Монитор**.
3. **Система** (службы, пакеты, пользователи, время) и **Логи**.
4. **Сеть** (+ firewall с откатом) и **Диски**.
5. **Cron, Docker, Центр уведомлений.**
6. Дополнительные утилиты (4.11) по приоритету.
