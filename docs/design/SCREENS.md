# Sherpa — экраны и навигация (MVP)

Макеты Figma: https://www.figma.com/design/zDfWDcd9Cknf69Iew4j8FV

- **Страница «v2 — Kali/KDE» — актуальная.** Стиль Kali Linux + KDE Plasma (Breeze Dark). Кадры: главное окно (dark и light), форма подключения, терминал, импорт, первый запуск, диалог host key, настройки. Тёмная тема основная, светлая — только для главного окна.
- Первая страница — v1 (нейтральный стиль), оставлена для истории.

Принципы: одна структура экранов и один визуальный стиль Kali/KDE на Linux и Windows (Qt 6 / QML, свои контролы), минимум хрома, действия — в один клик. Тексты ru/en: ядро отдаёт коды ошибок, фронт переводит.

## 1. Карта навигации

```
Первый запуск (один раз) ──► Главное окно
Главное окно
 ├─ Боковая панель: Все серверы / Группы / Теги / Импорт
 ├─ Список серверов  ──► Карточка сервера (правая панель)
 ├─ Форма подключения (диалог: создать / изменить / дублировать)
 ├─ Импорт ~/.ssh/config (диалог: предпросмотр → отчёт)
 ├─ Терминал (вкладки в том же окне, вкладка «Серверы» всегда первая)
 ├─ Диалог host key (первый ключ / ключ изменился)
 └─ Настройки (язык, тема, таймаут проверки, путь и экспорт ключ-файла)
```

Главное окно трёхпанельное: боковая панель 220 px, список ~470 px, карточка — остальное. Терминал открывается вкладкой рядом со списком: вкладка «Серверы» остаётся слева, вкладки сессий — правее.

## 2. Экраны

### 2.1 Первый запуск
- **Назначение:** ядро создаёт ключ-файл, пользователь сохраняет копию.
- **Элементы:** логотип, пояснение (секреты шифруются ключ-файлом, без него не восстановить), путь к ключ-файлу, «Сохранить копию…», «Позже», ссылка «Импортировать из ~/.ssh/config».
- **Состояния:** загрузка — спиннер, пока ядро создаёт ключ; ошибка (нет прав на каталог, диск) — баннер с текстом и «Повторить»/«Выбрать другой путь»; успех копии — уведомление «Копия сохранена».
- **Сценарий:** окно → ядро создаёт ключ → «Сохранить копию…» (диалог выбора файла, `sherpa-core` экспортирует) → главное окно. «Позже» — в главном окне остаётся ненавязчивый баннер до первой копии.

### 2.2 Главное окно
- **Назначение:** обзор парка, поиск, статусы, быстрые действия.
- **Заголовок:** название, поле поиска (имя, хост, теги), «Проверить все», «+ Добавить».
- **Боковая панель:** «Все серверы», группы со счётчиками (контекстное меню: переименовать, удалить), теги (клик — фильтр), «Импорт из ~/.ssh/config».
- **Список:** строка = индикатор статуса, имя, `user@host:port`, метка группы; статус: зелёный онлайн, красный ошибка авторизации, жёлтый офлайн, серый не проверялся (есть и текст/иконка — цвет не единственный признак). Двойной клик — терминал.
- **Карточка:** имя, статус и время проверки, поля подключения, host key (отпечаток и дата), «Терминал», «Проверить», «Изменить», «Дублировать», «Удалить» (с подтверждением).
- **Состояния:**
  - пусто — иллюстрация и две кнопки: «Добавить сервер», «Импорт из ~/.ssh/config»;
  - пустой поиск — «Ничего не найдено» и «Сбросить фильтр»;
  - загрузка — скелетон строк; во время проверки у строки спиннер вместо точки;
  - ошибка ядра — баннер сверху с кодом и «Повторить»;
  - массовая проверка — прогресс «Проверено 42 из 100», проверка параллельная, отмена.
- **Сценарий «Проверить»:** кнопка в карточке или «Проверить все» → спиннер → статус и время; ошибка показывает понятную причину (хост недоступен, неверный пароль/ключ, таймаут).

### 2.3 Форма подключения
- **Назначение:** создать, изменить, дублировать (заголовок «Копия: …», имя с суффиксом).
- **Поля:** имя*, хост*, порт (22), пользователь*, способ входа (сегмент: пароль / ключ-файл / ключ-текст), секрет по способу, парольная фраза, группа (с созданием), теги (чипы), описание.
- **Действия:** «Проверить» (не сохраняя), «Отмена», «Сохранить». Результат проверки — строка под полями.
- **Состояния:** валидация под полем (пустое имя, порт 1–65535, дубль имени); проверка идёт — спиннер, кнопки блокируются; ошибка проверки — красная строка с причиной, сохранить всё равно можно; несохранённые изменения — подтверждение при закрытии.
- **Секреты:** показываются маской, кнопка «глаз»; при редактировании существующий секрет не возвращается фронту, поле пустое с подсказкой «не менять».

### 2.4 Терминал
- **Назначение:** базовая интерактивная SSH-сессия.
- **Элементы:** панель вкладок (индикатор статуса, имя, закрыть, «+» — выбор сервера), область терминала, строка состояния (сервер, отпечаток ключа, размер).
- **Состояния:** подключение — спиннер внутри вкладки; обрыв — оверлей «Соединение потеряно» с «Переподключиться» и «Закрыть»; ошибка входа — как в проверке, с «Изменить подключение»; смена host key — диалог 2.6.
- **Закрытие:** вкладку с активной сессией закрываем с подтверждением. Выход из `exit` оставляет сообщение «Сессия завершена» и «Переподключиться».
- Терминал всегда тёмный в обеих темах окна; шрифт моноширинный, масштаб Ctrl +/−.

### 2.5 Импорт ~/.ssh/config
- **Шаги:** выбор файла (по умолчанию `~/.ssh/config`) → предпросмотр → отчёт.
- **Предпросмотр:** список хостов с чекбоксами, имя, `user@host:port`, путь ключа, метка («новый» / «уже есть — будет пропущен»), «Выбрать все / снять», счётчик. Шаблоны (`Host *`) не показываются как серверы; в подсказке — что они применены как значения по умолчанию. `Include` разворачивается.
- **Отчёт:** создано N, пропущено M (с причинами), ошибок K; кнопка «Закрыть» и переход к группе импорта.
- **Состояния:** файл не найден — пусто с «Выбрать файл…»; ошибка разбора — строка с номером строки в конфиге; загрузка — спиннер.

### 2.6 Диалог host key
- **Первое подключение (TOFU):** сервер, алгоритм, отпечаток SHA256; «Доверять и подключиться» (по умолчанию не нажата Enter'ом), «Отмена».
- **Ключ изменился:** красный заголовок «Ключ сервера изменился», предупреждение про MITM, «Был» и «Стал», главное действие — «Отмена» (по умолчанию), вторичное — «Принять новый ключ…» с дополнительным подтверждением. Подключение до решения заблокировано.

### 2.7 Настройки
Язык (ru/en), тема (системная/светлая/тёмная), таймаут проверки (по умолчанию 10 с), путь ключ-файла и «Экспортировать копию…». Окно настроек — страница, не мастер.

## 3. Сценарии

| Сценарий | Шаги |
|----------|------|
| Первый запуск | 2.1 → сохранить копию / позже → пустое главное окно |
| Добавить сервер | «+ Добавить» → форма → «Проверить» → «Сохранить» → сервер выбран в списке |
| Проверить | карточка «Проверить» или «Проверить все» → статус и время в списке |
| Открыть терминал | двойной клик или «Терминал» → вкладка → (при необходимости диалог host key) → сессия |
| Импорт | «Импорт…» → предпросмотр → снять лишнее → «Импортировать» → отчёт |
| Смена host key | проверка или терминал видит другой ключ → диалог 2.6 → «Отмена» или осознанное принятие |

## 4. Горячие клавиши

Одинаковы на Linux и Windows; в таблице `Ctrl` — основной модификатор (на Linux/Windows это Ctrl; если позже появится macOS — Meta/Cmd).

| Действие | Клавиши |
|----------|---------|
| Добавить сервер | Ctrl+N |
| Поиск | Ctrl+F |
| Проверить выбранный / все | Ctrl+R / Ctrl+Shift+R (F5 / Ctrl+F5 — алиасы) |
| Открыть терминал | Enter на строке |
| Следующая / предыдущая вкладка | Ctrl+Tab / Ctrl+Shift+Tab (Ctrl+PgDn / PgUp — алиасы) |
| Перейти на вкладку N | Alt+1…9 |
| Закрыть вкладку | Ctrl+Shift+W |
| Копировать / вставить в терминале | Ctrl+Shift+C / V |
| Изменить / Удалить | Ctrl+E / Delete |
| Настройки | Ctrl+, |
| Справка по клавишам | Ctrl+? |

В терминале Ctrl+C и Ctrl+V уходят в сессию (SIGINT/вставка не перехватываются). Реализация — `Shortcut`/`StandardKey` в QML.


## 5. Единый стиль Sherpa (Qt 6 / QML)

Тулкит — **Qt 6 + QML на обеих ОС** (Linux, Windows): один код интерфейса и один визуальный стиль Kali/KDE (раздел 6). Нативные контролы ОС не используются — свой набор контролов на `QtQuick.Controls` (стиль `Basic`/`Fusion` как база, переопределённый под Sherpa).

- **Структура:** `ApplicationWindow` без системной рамки (frameless) или с системной; три панели на `SplitView`, список — `ListView` с делегатами, карточка — `Item` справа. При ширине < 900 px карточка открывается поверх списка (`StackView`).
- **Свои контролы:** `SButton` (primary/secondary/danger, свечение через `MultiEffect`), `STextField`, `SSegmented`, `SChip`, `SStatusDot`, `SCheckBox`, `SSlider`, `STab`, `SDialog`. Все берут цвета из синглтона `Theme.qml`, так что смена темы и акцента — одна точка.
- **Полупрозрачность и blur:** окно с `color: "transparent"` и флагом прозрачного окна; размытие фона окна — композитором ОС (KDE Plasma — KWin blur, Windows 11 — Acrylic/Mica через платформенный хук). Внутренние панели — `MultiEffect { blurEnabled: true; blur: 1.0; source: ShaderEffectSource }` поверх фона окна. Если blur недоступен (GNOME/Wayland без расширения, старый Windows, «уменьшить прозрачность» в ОС, слабая видеокарта) — панели становятся непрозрачными с теми же цветами; настройка «Прозрачность окон» в «Настройках» это переключает.
- **Терминал:** собственный QML-компонент поверх эмулятора (выбор библиотеки — на этапе реализации; требуется 256 цветов/truecolor, выделение, прокрутка, ссылки); фон — полупрозрачный `Rectangle` с `MultiEffect`; моноширинный шрифт JetBrains Mono (поставляется в ресурсах приложения).
- **Диалоги:** `SDialog` — модальный `Popup` по центру, затемнение фона, действие по умолчанию — безопасное (в host key — «Отмена»), `Esc` закрывает, `Enter` — основное.
- **Уведомления и пустые состояния:** тост снизу справа и `SEmptyState` (иконка, текст, кнопки).
- **Доступность:** `Accessible.name/role` у всех контролов, навигация Tab/стрелками, видимый фокус (cyan-рамка), контраст ≥ 4.5:1, масштабирование по системному DPI и размеру шрифта.
- **Платформенные отличия (только мелочи):**
  - заголовок окна: на Linux — собственный в стиле Sherpa (кнопки справа, как в макетах) или серверный, если композитор его навязывает; на Windows — системная рамка с `Mica`/`Acrylic` или собственный заголовок с системными кнопками (Snap Layouts на кнопке «развернуть»);
  - модификатор горячих клавиш: Ctrl на обеих ОС (Meta/Cmd — для будущей macOS);
  - пути и диалоги выбора файла: системные (`FileDialog`), пути показываются в виде ОС (`~/.config/sherpa/key.bin` на Linux, `%APPDATA%\Sherpa\key.bin` на Windows);
  - шрифт интерфейса: системный (Noto Sans/Cantarell на Linux, Segoe UI Variable на Windows) или Inter из ресурсов — единый выбор для обеих ОС при реализации.

## 6. Визуальный стиль (v2: Kali / KDE)

Тёмная тема основная, светлая вторичная. Окна полупрозрачные с размытием фона (в Figma — `BACKGROUND_BLUR`), плотная информативная вёрстка в духе KDE Plasma, неоновые акценты как в Kali.

### 6.1 Палитра (тёмная тема)

| Роль | Цвет | Применение |
|------|------|------------|
| Фон окна | `#12151E`, 74% | основная поверхность |
| Боковые/служебные панели | `#05070C`, 35–55% | заголовок, сайдбар, статус-бар, поля ввода |
| Карточки, строки | белый 5%, обводка белый 10% | строки списка, группы полей |
| Текст | `#E6EAF2` / вторичный `#8B93A7` | основной / подписи |
| Kali Blue (акцент) | `#367BF0` | выбор, главная кнопка (с неоновым свечением) |
| Cyan | `#00E5FF` | хосты, отпечатки, ссылки, фокус поля, ключ-файл |
| Green | `#3DFF8A` | online, успех |
| Amber | `#FFC53D` | offline, пропуск |
| Red | `#FF4D6D` | ошибка авторизации, смена host key, удаление |
| Purple | `#B388FF` | метка группы |
| Серый | `#6B7488` | не проверялся |

Светлая тема: фон окна `#F4F6FA` 78%, панели белые 55%, текст `#1B2030` / `#5B6477`. Акценты затемнены ради контраста: cyan `#007C99`, green `#0E9A4A`, amber `#A86F00`, red `#D61F45`; Kali Blue прежний.

Фон рабочего стола в макетах — тёмный градиент с размытыми пятнами cyan/blue/purple, чтобы показать blur и прозрачность.

### 6.2 Прозрачность и размытие
- Окно и диалоги: непрозрачность 74–78%, blur 30 px, обводка 1 px белая 14–20%.
- Терминал: непрозрачность 62% (настройка 30–100%), blur 30 px, как в терминале Kali.
- Диалоги: свечение цвета смысла — синее обычное, красное для host key.
- Статусные индикаторы — яркие точки со свечением (glow ~7 px). Статус дублируется текстом (`online · 38 ms`, `auth failed`), цвет не единственный признак.
- Реализация: Qt Quick — `MultiEffect` для внутренних панелей и свечения, blur окна через композитор ОС (см. раздел 5). Если blur недоступен или включён режим «уменьшить прозрачность», окна становятся непрозрачными с теми же цветами.
- Единообразие: один стиль на обеих ОС; радиусы, отступы и цвета берутся из `Theme.qml`, а не из системной темы.

### 6.3 Шрифты
- Интерфейс: Inter (как в макетах), шрифт поставляется в ресурсах приложения; запасной — системный.
- Моноширинный (хосты, `user@host:port`, порты, отпечатки, время ответа, пути, статус-бар, значения в карточке, терминал): JetBrains Mono. Шрифт поставляется вместе с приложением, одинаков на обеих ОС. Размеры: интерфейс 12–13, моно 11–13, заголовок карточки 20.
- Терминал: промпт в стиле Kali двухстрочный — `┌──(user@host)-[dir]` / `└─$` — синие рамки, cyan пользователь и хост, белый путь и команда; успех зелёным, ошибки красным.

### 6.4 Плотность
Строка сервера 48 px, поля ввода 34 px, отступы 8/12/22. Таблицы без разделителей, строки группируются фоном. В главном окне три панели (210 / 480 / остальное) плюс статус-бар со сводкой: online / error / offline.

### 6.5 Экран «Настройки» (2.7)
Окно с левой навигацией: Общие, Внешний вид, Подключения, Терминал, Безопасность, О программе. «Внешний вид»: язык (ru/en), тема (системная / тёмная / светлая), прозрачность окон, размытие фона, акцентный цвет (5 пресетов), шрифт терминала; «Подключения» — таймаут проверки (по умолчанию 10 с); «Безопасность» — путь ключ-файла и «Экспортировать копию…».
